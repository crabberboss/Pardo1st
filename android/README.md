# 帕朵一号 Android

原生 Android 外壳内置离线页面和 SQLite 数据库；运行时无需安装 Python 或其他依赖。支持 Android 8.0 及以上。

## 功能

- 导入 `.txt`、`.md` 小说时自动按章节号本地切分；可在“章节切分”区预览、填写自定义标题表达式并重新切分。逐章调用选定 API 生成关键词、剧情概览、人物与关系、地点/物品/设定、伏笔与未解问题，失败章节可续建；预览按栏目展示。
- UTF-8 编码检测允许采样末尾是未完整读取的汉字；对已有超大单章，章节预览、切分预览与导出均以小段读取，避免 Android `CursorWindow` 单行大小限制。原文预览按每页 12,000 字加载。
- 导入桌面端 `.novel-memory.json` v2–v4 知识库，导出为 v4。知识库含原文、章节总结、特殊标签等，不含 API 密钥、对话或改写稿。可在知识库页删除当前手机存档，不会删除已导出的文件或其他存档。
- 删除、重新切分、清空对话等需要确认的操作使用安卓原生确认弹窗；知识库删除状态会留在列表下方，取消或失败时不会误显示成功。
- 对话页为移动端气泡聊天界面：右上角专管对话存档，输入栏旁“功能”包含知识库与模式、角色卡、预设等设置。仅消息区域可滚动，滚动条隐藏。旧版对话在数据库升级时自动迁入“原有对话”。
- 单章改写；以当前知识库统一提示词改写全书；特殊关键词从当前库直接点选组合筛选，普通关键词仍可补充搜索。改写页可分段查看原文与编辑生成稿，任务可暂停，续建时可跳过已改写章节。开始批量改写前会显示章节数和输入原文字数估算。
- 手机知识库页可新建、编辑、删除特殊关键词，并为当前章节挂靠标签和 30 字以内情节说明；名称、颜色、识别提示词及章节挂靠使用桌面端相同的知识库 v4 字段，导出后桌面端可继续编辑。已定义标签在章节总结的同一次 API 请求中识别，不额外发起标签识别请求；人工标注优先于模型结果。
- 改写模板使用桌面与安卓共同支持的 `novel-memory-rewrite-template` v1 独立 JSON，包含标签组合、全局/章节提示词及改写规则。每个手机知识库可保存一个本地模板，并可通过系统文件窗口导入、导出；桌面端现有“导入组合模板”可直接读取。示例见 `../novel_memory/rewrite-template-example.json`。
- 改写稿使用独立的 `.novel-memory-rewrites.json` 文件与桌面端互通，导入时校验文档名、章节名及原文 SHA-256。
- 知识库和改写稿导出均可自行命名，直接保存到手机“下载/NovelMemory”，也可使用系统文件窗口另选位置。保存后界面显示文件名和位置。
- 知识库章节浏览以每页 40 章显示，可输入页码直接跳转；知识库列表不再显示改写状态，改写状态留在改写页。
- 手机知识库的章节原文可分段编辑或删除。编辑只修改手机知识库，不碰导入的源文件；编辑后该章总结和特殊标签失效，已有改写稿保留并提示校对。删除章节会清理该章的总结、标签命中、原文修改记录与改写稿，不影响其他知识库。
- 统一改写提示词按知识库持久保存，旧版页面本地值会按知识库迁移一次；本章提示词及额外要求按章节自动保存，生成成功后与最新改写稿一起保留。切换章节不会清空统一提示词，切换知识库时载入对应值。模板提示词留在独立模板 JSON 中。为了避免分享知识库时泄露个人预设，知识库导出不含统一提示词，请另行导出模板文件。
- DeepSeek、硅基流动、OpenRouter、LM Studio 四套 API 配置分别保存；API Key 使用 Android Keystore 加密，不导出。设置页可读取当前渠道模型列表并下拉选择，也可手填模型 ID；连接测试显示渠道、地址、模型、HTTP 状态码与脱敏错误，并区分认证失败、模型不存在、额度不足、限流与超时。DeepSeek 的 `deepseek-chat` / `deepseek-reasoner` 已于 2026-07-24 退役，默认改用 `deepseek-v4-flash`。
- 生成时章节列表和当前章节正文会随每次保存同步刷新，默认跟随当前生成章节；手动选章后保留所选章节，点击“跟随生成”可恢复自动跟随。
- “文章生成”工作区按项目设定、章节细纲、生成进度、角色与事件、成稿正文分页面组织。新建只需小说名和主角名字；世界观、系统规则、主角设定、文风与本章细纲均有 LLM 扩写入口，扩写提示词及各栏独立的输出 Token 上限集中在设置页修改，项目设定保存后显示明确成功或失败状态。全书方向参考可留空，只在下一章细纲规划时低优先级、限量提供给模型；正文生成请求不包含全书方向参考。每章同时规划普通关键词、特殊场景标签与出场角色；可选择自动出场或逐章确认，手动编辑下一章章纲。角色池按最近出场计算热度，事件线记录逐章进展，能力、数值、物品与世界状态独立保存。章节时间轴显示角色与梗概；每阶段自动保存，支持暂停、恢复、失败重试和项目 Token 预算。剧情规划接口仅预留注释，不调用其他项目的逻辑。生成项目不会自动修改知识库。
- 角色卡可直接导入 SillyTavern V2/V3 JSON，或含 `chara`/`ccv3` 元数据的 PNG；导入前显示字段映射预览，确认后才写入当前知识库。未知字段、角色书、备选开场白与标签保存在扩展区，不丢失；导入只解析数据，不执行任何脚本。

## 使用注意

- 在手机连接电脑上的 LM Studio 时，API 地址必须填写电脑的局域网 IP，例如 `http://192.168.1.5:1234/v1`，而不是 `127.0.0.1`。电脑须允许局域网访问。
- 整章改写需要模型拥有足够的上下文和输出空间。模型返回截断时，本章会标记失败且不会保存不完整稿。
- 批量任务逐章保存，可在应用内暂停；如果应用被系统终止，可重新打开并选择“跳过已改写章节”续建。当前初版尚不支持应用被关闭后自动在后台继续调用 API。
- 小说生成在应用运行期间连续执行；关闭应用会中断当前网络请求，下次可从已保存的规划、正文草稿或记忆提取阶段继续。严格状态核对只检查明确的正文依据与基本数值边界，复杂设定冲突仍需人工校对；实际 Token 用量由服务商返回，缺失时显示估算值。当前尚未接入另一项目的剧情规划器。
- 章节总结对长章使用头、中、尾抽样，以降低输入成本；可能漏掉中间细节，重要章节建议在桌面端校对。
- “全书索引”在本地由各章摘要生成，不额外调用 API。它不是独立的模型全书总结。
- 如果旧版本已把 UTF-8 小说误识别为乱码并保存为 1 章，请在新版中重新导入原 `.txt`，生成一个新的知识库；旧知识库不会被删除。仅对旧乱码存档执行“重新切分”无法恢复原文编码。
- 对“超大单章且原文出现大量替换字符”的旧存档，首页会显示明确警告与重新导入入口，避免误把乱码切分当成修复。

## 构建与验证

项目使用 Android Gradle Plugin 8.9.2、Gradle 8.11.1、JDK 17 与 Android SDK 35。执行 `gradle testDebugUnitTest assembleDebug` 后，调试 APK 位于 `app/build/outputs/apk/debug/app-debug.apk`。

自动化测试覆盖小说切分、知识库往返、改写稿往返、关键词筛选及 API 适配请求。发布前仍需在真实设备或可运行的模拟器中完成安装、文件选择器、WebView、联网及长任务验收。
